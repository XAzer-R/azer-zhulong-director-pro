# Contributing, security, and licensing

## Contributing

Use a focused Issue or Pull Request with a reproducible problem, proposed behavior, and verification results. Workflow changes must keep the coordinator, roles, Skills, templates, and documentation consistent.

Run the package validator and regression suite listed in the README. Do not commit client materials, unpublished scripts, novels, unlicensed frames, credentials, or personal conversation logs. Explain the source and license of any proposed third-party content; removing attribution is not a substitute for permission.

The source [contribution guide](../../CONTRIBUTING.md) is currently in Chinese.

## Security reports

Never publish secrets, personal information, or sensitive exploit details in an Issue. Prefer the repository's GitHub Security private reporting feature if it is enabled. If no private channel is available, send a public contact request without sensitive details and wait for the maintainer to provide a private route. This documentation does not claim that private reporting has been enabled.

See the source [security policy](../../SECURITY.md).
